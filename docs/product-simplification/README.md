# Упрощение SafeHaul: план и прогресс

**Цель:** сделать SafeHaul меньше, понятнее и быстрее в работе, не перестраивая его и не добавляя лишних функций.
**Основа:** аудит [`audit.md`](audit.md) — только чтение кода, версия `main` `6b4746da` от 2026-11-05.

**Как читать отметки:**
- `[ ]` — ждёт;
- `[~]` — в работе;
- `[x]` — сделано и проверено (с PR и тестами);
- **Заблокировано** — нужен ваш ответ, вопрос рядом;
- **Пропущено** — не делаем, причина рядом.

«Слито» значит, что изменение в `main` и выложено на Testing. Серверная часть общая, поэтому она сразу меняется
и для Production. Экраны Production меняются только после вашего выпуска.

## Как идёт работа

- **Порядок.** Пакеты идут по порядку. Один пакет — один PR на ветке `claude/hopeful-brown-j6zg6b`. Пакет сливается,
  когда проверки зелёные и замечания ревьюера разобраны (ваше решение Д1 от 2026-11-04).
- **Каждая задача проходит одни и те же шаги:**
  1. причина;
  2. исправление;
  3. тест, который сначала падает;
  4. самопроверка;
  5. повторные тесты;
  6. описание приложения (`docs/APP_BRIEF.md`) в том же PR;
  7. отметка здесь.
- **Без вашего разрешения не трогаю:**
  - правила доступа к базе;
  - права;
  - адреса страниц;
  - удаление записей.
- **Снимки экранов:** новые берутся из проверки GitHub, и я сначала смотрю каждый.
