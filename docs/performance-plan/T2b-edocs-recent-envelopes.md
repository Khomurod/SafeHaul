### Design (decided here, so the executor does not re-derive it)

- A live **window**: the newest 100 by `createdAt desc`, growing by 100 on "Load older documents". Every loaded row stays live (sealing, signing and Void update in place, as today).
- While the window holds everything (fewer than 100 documents): nothing else is read; numbers and the attention list are computed in the browser exactly as today. Small carriers see no change.
- When the window is full (`hasMore`): (1) five server counts (`getCountFromServer`) for total, awaiting, awaiting-with-failed-delivery, completed and needs attention; (2) a second live listener on the documents that need attention (one `or()` query, newest 100) feeds Overview's Needs attention list and the Sent table while "Needs attention only" is on — with its own loading and error states, never a silent empty list.
- Search and the other filters keep running in the browser over the loaded rows (the owner decision), with a notice.

   - `useLiveQueryWindow({ buildQuery, resetKey, pageSize, enabled = true, mapDoc = (d) => ({ id: d.id, ...d.data() }), errorMessage, logLabel })` → `{ docs, isLoading, error, hasMore, loadMore, isLoadingMore, loadMoreFailed, retry, snapshotVersion }`.
   - `buildQuery` (returns a Query without a limit) and `mapDoc` are held in refs and called inside the effect; only `enabled`, `resetKey`, the window size and `retry` re-subscribe. Subscribe `onSnapshot(query(buildQuery(), limit(windowSize)), next, fail)`; unsubscribe on cleanup.
   - When `enabled` turns true or `resetKey` changes: window back to `pageSize`, docs cleared, and `isLoading` true **in that same render** (render-time adjustment, the pattern at `EnvelopeHistory.jsx:392-397`), so a newly enabled list never paints an empty state first.
   - `next`: `docs = snapshot.docs.map(mapDoc)` (test mocks have no `size`); while a load-more is pending, ignore a snapshot with `snapshot.metadata?.fromCache === true` that has fewer docs than are shown (the memory cache can answer a re-listen with what it still holds); otherwise set docs, `hasMore = docs.length >= windowSize`, clear loading flags and error, remember this window size as the last good one. `snapshotVersion` increments on every snapshot after the first of each subscription (the first answer of a new or grown window is not a change).
   - `fail`: `console.error(logLabel, err)`; if a load-more was pending → `loadMoreFailed = true` and go back to the last good window (rows stay); otherwise `error = errorMessage`, `isLoading = false`.
   - `loadMore`: no-op unless `hasMore` and not already loading; clears `loadMoreFailed`; grows the window by `pageSize`; keeps the rows on screen while the bigger window arrives.
   - `retry`: clears `error`, sets `isLoading`, re-subscribes. Disabled: no subscription, `docs = []`, `isLoading = false`, `hasMore = false`.

New `src/shared/hooks/useServerAggregate.js`: `useServerAggregate({ run, enabled, refreshKey, intervalMs = 2000 })` → `{ value, isLoading, error, refresh }`. `run` is an async function held in a ref. When `enabled` turns true it runs at once (`isLoading` true in that same render). A later `refreshKey` change starts ONE timer of `intervalMs` if none is pending; changes while it is pending fold into it — a fixed batch window, not a debounce, so a steady stream of changes (a running campaign in T2c) still refreshes every 2 s instead of never. `refresh()` runs at once (Try again). A version ref drops stale answers; a failure is `console.error`ed, `value = null`, `error` set; disabled → no call, `value = null`, pending timer cleared; unmount clears the timer.

## Risks and safeguards

- A missing or still-building index breaks only the attention listener, and only for carriers with more than 100 documents: Overview and the Sent table then say "Documents that need attention could not be loaded." with Try again — never "Nothing needs attention". Safeguards: the indexes ship in the same PR, an index test pins them, the counts need no composite index, and promotion waits for Enabled. Production keeps its current frontend until promoted.
- If a count query is refused (e.g. Firestore asks for an index with FAILED_PRECONDITION), the Overview shows '—' and "Totals could not be loaded.", not wrong numbers; add the index the console error names in a follow-up PR.
- Status case: the client lowercases `status`, server counts match exactly; every writer at 11626a6 writes lowercase, so a document with a capitalised status could only come from outside the app — it would be listed but not counted.
- Reads: today every visit reads the whole history; after, at most 100 + up to 100 attention rows + five counts (one read per 1,000 entries each), plus recounts at most every 2 s while loaded documents change. "Load older documents" re-reads the bigger window (100 → 200 reads) — the price of keeping every row live.
- Counts can lag for an older document changed outside the window until the next change or visit (documented in §12).
- The table pager counts loaded rows ("Showing 1–25 of 100 documents") while the notice above it gives the full total; both are true, and the notice explains the difference.
- Bundle: `or`/`and` add a little to the startup `vendor` chunk; `check:bundle-budget` must pass without raising its ceiling.
- CI: editing `firestore.indexes.json` runs the full suite (`scripts/ci-plan-rules.mjs:80`); expect a longer run.
- Search scope narrows for large carriers (the owner decision); the notice says so. Void, Correct, Copy link and Download act on rows in the live window exactly as before.
- Rollback: revert the PR. Leave the indexes; they are harmless, and deleting them is a separate owner-approved change.
