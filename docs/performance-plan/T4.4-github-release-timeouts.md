# T4.4. Add a 15-second limit to the GitHub reads behind Releases, but not to the dispatch that starts a release

[← Plan, progress and owner decisions](README.md) · Checked at commit `11626a6` on 2026-11-03; re-check line numbers against the current `main` before you start.

- **Checklist item(s):** #12 — Set timeouts for external API calls (GitHub release calls, owner-only)
- **Size:** S · **Pull requests:** 1 · **Depends on:** none · **Owner decision needed:** none
- **Why it matters for users:** Only the owner uses it. When GitHub is slow, Super Admin → Releases and the Telegram release offer wait until their function is killed. After this task they say "GitHub could not be reached… Try again in a moment" within 15 seconds. The request that actually starts a Production release keeps no limit, because a dispatch whose answer was lost may already have started a release.

## Current behaviour (verified at 11626a6)

- `mintInstallationToken` (`functions/releaseManagement/github.js:168-199`, fetch at `:172-182`) and `githubRequest` (`:216-244`, fetch at `:222-231`) pass no `signal`. Both use the built-in `fetch` (or an injected `fetchImpl`), so they are bounded only by Node's own defaults (not re-checked) and the function limit: the release callables run with the 60 s default (`functions/releaseManagement/index.js:53-56, 66, 126, 147`), `offerProductionRelease` is scheduled with `retryCount: 0` (`functions/ops/releaseOffer.js:130-136`).
- `githubRequest` callers: `createReleaseApi` GETs (`github.js:247-249`, used by `releaseManagement/index.js:86`, `releaseManagement/promote.js:69` and `ops/releaseOffer.js:139`), `listPromotionRuns` GET (`github.js:300-307`, used by `releaseManagement/index.js:95` and `ops/releaseFollow.js:87`, which already catches any error and tries again on its next run, `:86-90`), and `dispatchPromotion` **POST** (`:259-275`, used only by `promote.js:215`).
- On any dispatch error, `promote.js:214-233` concludes "the dispatch never happened": it deletes the lock and records `dispatch-failed`. A dispatch that timed out after GitHub accepted it would free the lock while a release runs. That is why the dispatch must not get a client-side limit. A token mint that times out before the dispatch is different: nothing was dispatched, so the existing "never happened" path is correct.
- `GithubRequestError` (`github.js:76-81`) is turned into `HttpsError('unavailable', 'GitHub could not be reached to run the release. Try again in a moment.')` by `safeFailure` (`functions/releaseManagement/promotionStore.js:41-55`). A timeout can reuse this path.
- `createGithubApi` in `functions/releaseManagement/eligibility.js:461-473` is used only by release-pipeline scripts in GitHub Actions (`scripts/check-release-health.mjs:46, 238`; `scripts/resolve-testing-release.mjs:33, 56`; `scripts/resolve-deploy-base.mjs:53, 155`), not by any Cloud Function; no script imports `github.js`.
- The existing pattern for a timed fetch whose body is read under the same limit: `functions/ops/telegram.js:48-70` (AbortController, `setTimeout`, `clearTimeout` in `finally`).
- The callables, offer and follow tests mock `github.js` as a whole (`releaseManagement.callables.support.js:120-128`, `opsReleaseFollow.test.js:16`), so only `releaseManagement.github.test.js` exercises the real fetches.

## Scope

- In: `github.js` — a 15 s limit for `mintInstallationToken` (minting a second token is harmless) and for `githubRequest` when `method === 'GET'`, kept until the body has been read; a timeout becomes `GithubRequestError(..., 504)`; tests; APP_BRIEF §7 GitHub row.
- Out (do not do in this task): the dispatch POST (reason above); `eligibility.js` `createGithubApi` and every `scripts/` file (release pipeline; changing them would need `.claude/rules/release-pipeline.md` and `npm run check:ci-plan`); `ops/releaseFollow.js` itself (its own 10 s limit covers only the `release.json` read, `:21, 35-45`; its GitHub read gains the new limit through `listPromotionRuns` without any edit); no index, CSP or data change.

## Implementation steps

1. Tell the owner in at most three plain Russian lines, stressing that starting a release is not limited.
2. Failing tests first (see Tests): a GET whose `fetchImpl` never answers rejects with `GithubRequestError` status 504 after 15 s.
3. `github.js`: after `GITHUB_API` (`:49`) add `const GITHUB_TIMEOUT_MS = 15000;` with a comment that reads and token minting give up after 15 s, and the dispatch is deliberately unlimited (`promote.js` treats a failed dispatch as never started).
4. Add a local helper `async function timedGithubCall(work)` that creates an `AbortController`, starts `setTimeout(() => controller.abort(), GITHUB_TIMEOUT_MS)`, returns `await work(controller.signal)` (the callback does the fetch **and reads the body**), and in `catch` rethrows a `GithubRequestError` as it is but turns any other error while `controller.signal.aborted` into `new GithubRequestError(`GitHub did not answer within ${GITHUB_TIMEOUT_MS / 1000} seconds.`, 504)`; `clearTimeout` in `finally`. Same shape as `ops/telegram.js:48-70`.
5. `mintInstallationToken`: move the fetch, the `!response.ok` check and `response.json()` with its token check (`:172-198`) into `timedGithubCall((signal) => …)` and pass `signal` in the fetch init.
6. `githubRequest`: put the fetch, the `!response.ok` branch, the 204 branch and `response.json()` (`:222-243`) into one inner `send(signal)` function whose init adds the signal with the same conditional spread the body uses at `:230` (`...(signal ? { signal } : {})`), so a call without a signal builds exactly today's init. Then `return method === 'GET' ? timedGithubCall(send) : send(undefined);`. The dispatch POST is unchanged.
7. Docs, self-review (the token cache, `:161-210`, is unchanged; a timed-out mint caches nothing), PR. **Кратко** draft: "Экран Releases и предложение выпуска в Telegram теперь ждут ответа GitHub не больше 15 секунд и показывают «GitHub недоступен, попробуйте ещё раз». / Сам запуск выпуска не ограничен по времени — иначе потерянный ответ мог бы привести ко второму выпуску. / Проверено: тесты функций и линт. От вас ничего не нужно."
