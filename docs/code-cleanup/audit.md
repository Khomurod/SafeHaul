## Правила безопасности для любого удаления

1. **Сайт на Production старше, чем `main`, а сервер у Testing и Production общий.**
   - Серверную функцию нельзя удалять, пока её вызывает сайт, который сейчас открыт на
     Production.
   - Порядок такой: убрать вызов на сайте, выпустить Production, затем удалить функцию
     через список `RETIREMENTS` в `scripts/retire-functions.mjs`. Если функцию просто
     убрать из `functions/index.js`, она перестаёт выкладываться, но продолжает работать.
2. **Как проверить, вызывает ли что-то сайт на Production.**
   - Взять коммит последнего выпуска (Super Admin → Releases или deployment
     `production`).
   - Выполнить `git grep "'<имя>'" <коммит> -- src`. Клон для этого нужен полный
     (`git fetch --unshallow`).
3. **Серверные изменения только добавляют.** Новый вызов появляется рядом со старым, а
   входы и ответы старого не меняются.
4. **Вместе с кодом удаляются его тесты.** В том же PR правится `docs/APP_BRIEF.md`.

## 8. Технический долг: возможности

1. **Тестовые данные попадают в production-сборку.**
   - **Что.** `isE2ETestMode` (`src/lib/runtime/e2eMode.js:1`) зависит от одной переменной
     сборки. Только 3 из примерно 90 мест дополнительно проверяют
     `!import.meta.env.PROD`. Через эту же проверку проходит и вход под пробной учётной
     записью (`?e2eAuth=super_admin` в `DataContext.jsx:100`).
   - **Сейчас безопасно.** Выкладка эту переменную не включает, и тестовые ветки из сборки
     удаляются.
   - **Но в сборку уходят:**
     - сами тестовые данные. Около 12–15 КБ в 8 частях, в том числе текст «TEST FIXTURE —
       NOT LEGAL TEXT» в части анкеты;
     - отдельная часть `VOEPreviewHarness-*.js`, на которую ничего не ссылается. В ней
       тестовые подписи и проверочная строка XSS.
   - **Шаг.**
     - Одна строка: `isE2ETestMode = !import.meta.env.PROD && …`.
     - Тестовые данные отдавать функцией или пометить `/* #__PURE__ */`.
     - Тестовый `lazy()` в `App.jsx:29` закрыть той же проверкой.
     - После этого проверить сборку поиском этих строк.
     - Сами данные не менять: на них стоят эталонные снимки.
2. **APP_BRIEF больше своего лимита.**
   - Сейчас: 1993 строки и 136 КБ при пределе 1500 строк и 94 КБ (пока только
     предупреждение).
   - Правила проекта требуют сокращать документ, а не поднимать лимит. Отдельная задача.
3. **Проверка вызовов сервера видит не все вызовы.** Четыре функции вызываются через
   обёртку с именем в переменной, и `check-callable-contract.mjs:38` их не видит:
   - `saveCompanyPreparedApplication`;
   - `getCompanyPreparedDraft`;
   - `publishCompanyAgreementWording`;
   - `revertCompanyAgreementWording`.

   Любой список «никто не вызывает», построенный по этой проверке, для них неверен.
   Стоит научить проверку видеть такие обёртки.
4. **Холодный старт функций.** Модули-сборщики (`employmentVerification.js`,
   `integrations/index.js`, `bulkActions/index.js`, `companyAdmin.js`) грузят все свои
   части сразу. Это сводит на нет ленивую загрузку в `index.js`. Не срочно.
5. **Сервисный аккаунт ИИ-функций.** Три ИИ-функции первого поколения работают под другим
   сервисным аккаунтом. Один явный `serviceAccount` для всех убрал бы лишнюю проверку, но
   это изменение прав IAM, его делает только владелец.
6. **Автоматическая проверка неиспользуемого кода в CI** (knip с настройкой под проект).
   Это новая проверка, а правила проекта добавляют их только по необходимости. Решение
