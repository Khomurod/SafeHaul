# The SafeHaul component catalog

This is the catalog for SafeHaul's **design system** — the business-neutral
visual contract that owns how reusable interface elements look and behave.

It documents primitives and business-neutral page patterns. It deliberately does
**not** document feature screens, and it does not know that SafeHaul has drivers,
recruiters, carriers or signing requests. Fixtures here talk about *records*,
*owners* and *references*; features supply the real domain words at the call
site.

## Before you change UI code

Read these, in order:

1. `docs/SAFEHAUL_DESIGN_SYSTEM_ROADMAP.md`
2. `src/design-system/README.md`
3. The component or pattern documentation in this catalog

## Approval status

Every page in this catalog states a status. **Not everything here is approved**,
and the difference matters — an honest catalog is more useful than a flattering
one.

| Status | Meaning |
| --- | --- |
| **Approved** | The component is proven by real consumers, has behaviour and accessibility tests, and should be reused as-is. |
| **Needs review** | Built from approved primitives, but something about it is unsettled — a missing primitive, an open roadmap item, or verification that has not been automated yet. Usable, but read the caveat before copying it. |
| **Temporary** | A compatibility shim that exists only until a migration finishes. Do not add new consumers. |

Where a page says *Needs review*, it says exactly what is unresolved. Those
caveats are the roadmap's open items, not hedging.

**The two decisions that held the visible families were answered on 2026-09-04.**
The owner approved the semantic brand and action colours as they stand and
confirmed WCAG 2.2 AA as the permanent standard, which were the last two items in
roadmap section 6 blocking "declaring the affected families fully approved". A
page still marked *Needs review* is now waiting on something specific to itself,
not on a palette or a standard nobody had signed off.

## Icons

Every glyph comes from `@design-system/icons`, and it arrives as a **token**
rather than a component:

```jsx
import { Icon, Trash2 } from '@/design-system/icons';

<Icon icon={Trash2} size="sm" />        // decoration — announced by nothing
<Icon icon={Trash2} label="Delete" />   // the glyph IS the control
```

Sizes are the seven steps `xs sm md lg xl 2xl 3xl` (12–32px), never a pixel
number — `<Trash2 size={13} />` throws by name. A container that already sizes
the glyph inside it (`Button`, `IconButton`, `Tabs`, `SegmentedControl`,
`FileInput`) still wins, so an icon in a small button is small because the button
says so. See **Foundations → Icons**.

## Known gaps

**The authoritative list lives in one place, and it is not here.**
`docs/SAFEHAUL_DESIGN_SYSTEM_ROADMAP.md` section 5 — "Missing primitives that
live code is waiting on" — records every gap with the call sites that cite it and
the reason the nearest primitive does not fit. This page used to repeat that
list, and so did `src/design-system/README.md`; three copies of a list that
changes every slice is three chances to read a stale one.

What still belongs here is the rule, not the inventory: **do not hand-roll a
primitive that does not exist yet.** Record the need in section 5, with the call
site and what the nearest existing primitive cannot express. A hand-rolled one
becomes a second implementation the moment the real one lands, and this catalog
records that mistake happening twice already.

The same goes for a shape the design system already owns. A **hand-composed
pattern** — a card with a medallion, heading, body and actions, or a dialog with
its own cancel-and-confirm footer — is made entirely of approved primitives, so
it passes every automated rule while duplicating a pattern that exists. Use
`patterns/page-state` and `ConfirmDialog`.

## Recently closed

Closed on 2026-08-21, so the exceptions that cited them are retired:

- **Tabs** (`TabList` / `TabPanel`). Nine screens had hand-rolled the tablist and
  seven had each written the same keyboard handler.
- **Switch** (ARIA `switch`), promoted from a feature-owned implementation that
  was already correct.
- **SegmentedControl**, retiring four `role="group"` / `aria-pressed` exceptions.
- **Disclosure**, for a collapsible section whose trigger sits inside a heading.
- **FileInput**, the picker contract four upload controls were waiting on.
- **Link / ButtonLink / IconButtonLink**. `external` is the reason: every
  external anchor in the product opened a new tab with no announcement. Do not
  hand-write `target="_blank"`.
- **EmptyState / ErrorState / LoadingState** in `@design-system/patterns`. This
  catalog used to document the composition and ask you to copy it, which is a
  component waiting to be written.

Closed on 2026-09-05:

- **Chip / ChipGroup**, the interactive twin of `Badge`: the same pill, the same
  12px semibold text, the same six tints, plus a pointer, a focus ring and a
  pressed state. It closed **two** recorded gaps that turned out to be one
  primitive — the filter chip and the tinted chip link. Six exceptions retired
  across four files, and one screen-reader repair on the way: the candidate
  list's pipeline strip had neither a group name nor `aria-pressed`.
- **`pressed` on Button and IconButton**, for a toggle that must keep its
  variant. It draws a fill and an inset ring at a specificity nothing
  feature-side can beat — which is the point, because the two sort arrows it was
  built for marked the active direction with a text utility that lost to the
  variant's own `color` rule, and lost silently.
- A raw `<button aria-pressed>` is refused from here on. `SegmentedControl` and
  `Chip` are the two shapes; a `Button` with `pressed` is the third.

Closed on 2026-08-25:

- **`Button variant="link"`** — an action that reads as inline text. Six screens
  had written it by hand, in two font weights and three sizes between them. It
  is still a `<button>`, because it acts rather than navigates; use `Link` when
  the address bar changes.
- **Named brand colours** (`ds-brand-primary`, `ds-brand-accent`). The mark's own
  two colours were bare hexes in four places. The accent is for the inverse
  surface only — on a light one it is about 1.6:1.

Also closed on 2026-08-25, by **adoption** rather than by building anything:

- Every hand-rolled tab strip, toggle group and file picker in the product now
  uses `TabList`/`TabPanel`, `SegmentedControl` and `FileInput`. The primitives
  above had shipped on 2026-08-21 with zero, zero and two consumers while eleven
  tab strips, five toggle groups and nine raw file inputs stayed in the tree.
- Every status screen, panel-level empty and confirmation dialog uses
  `patterns/page-state` or `ConfirmDialog`. Fifteen states and six dialogs were
  still hand-composed out of the right primitives in the wrong shape, several of
  them written *after* the pattern existed.
- Every approved native `<table>` applies the `ds-native-table` contract, so a
  table that is not `DataTable` still gets `DataTable`'s header, divider, density
  and cell padding from the same `--ds-table-*` roles.

`PageState` gained three capabilities on the way, each because more than one
consumer had hand-written it: `titleId`, `children` and `focusOnMount`. Its
story page documents all three.

As of 2026-08-25 every remaining exception in the product carries a written
reason; none is left marked as migration debt. That does not make the gaps above
less real — an exception with a good reason is still a call site waiting for a
primitive.

## Appearance

SafeHaul ships a **light appearance only**. There is no `prefers-color-scheme`
rule, no `data-theme` attribute and no dark token set anywhere in the product, so
this catalog does not offer a dark-mode toggle — a switch that rendered something
the application cannot produce would be worse than none.

The backgrounds toolbar does offer an **inverse surface**. That is a *role* for a
specific kind of content — console and log output panels — not an appearance
setting.

## Viewports

Three presets, matching the widths SafeHaul reviews at:

- **Desktop — 1440**
- **Tablet — 1024**, where table action columns first compete for space
- **Mobile — 412**

Pattern stories carry explicit stories at all three.

## Safety guarantees

The catalog is safe to build and host anywhere:

- **No Firebase, Cloud Functions, Storage or any network call.** Nothing here
  imports application context or domain services, and
  `src/design-system/tests/architecture.test.js` fails the build if design-system
  code ever does.
- **No secrets.** The CI job that builds this catalog is given no credentials.
- **No production data.** Every value comes from
  `src/design-system/stories/fixtures.js`, which is entirely hand-written
  literals — no `Math.random`, no `Date.now()`, no generated data. Stories render
  identically on every run.
